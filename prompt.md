# Продуктовая стратегия RestoMind: от MVP к SaaS

## 1. Приоритеты развития (P0 — P3)

### 🔴 P0: Критическая надежность и Доверие
*   **Статусы сообщений (Messaging Reliability):** Внедрение прозрачного трекинга: `sending` (часики) → `sent` (галочка) → `delivered` (две галочки) → `failed` (ошибка с кнопкой «переотправить»).
*   **Multi-tenant архитектура:** Полная изоляция данных на уровне БД через `organization_id`. Каждый ресторан видит только свой контент.
*   **Dashboard «Про деньги»:** Главный экран должен отвечать на вопрос: «Сколько я заработал благодаря боту?». Вывод выручки, количества заказов и доли заказов через AI.

### 🟡 P1: UX Операционной системы (Sales OS)
*   **Трехуровневая навигация:** 
    1. **Overview** (стратегия/деньги).
    2. **Operations** (заказы/чаты).
    3. **Settings** (конфигурация).
*   **Интеллектуальная упаковка:** Визуальные карточки правил упаковки (например, «Манты → +200 ₸») с превью расчета для клиента.
*   **Мобильная адаптация:** Приоритет на управление заказами и чатами с телефона (для персонала «в полях»).

### 🟢 P2: Рост и Аналитика (AI → BI)
*   **Telegram для операторов:** Уведомления о новых заказах и эскалациях прямо в мессенджер персоналу.
*   **Deep iiko Analytics:** Анализ популярности блюд по времени суток и автоматическая подстройка стратегии Upsell.
*   **Onboarding:** Разделение базы знаний на «Справочник заведения» (адрес, часы) и «Характер бота» (стиль общения).

### ⚪ P3: Техплатформа
*   **Рефакторинг слоев:** Переход на чистую архитектуру (Domain, Service, Infra) после стабилизации логики корзины.
*   **SPA (Vite):** Перенос админки на современный JS-фреймворк при значительном усложнении интерактива.

## 2. Структура Dashboard (Центр принятия решений)

1.  **KPI Row:** Выручка сегодня, кол-во заказов, % конверсии, **AI Revenue** (доход от допродаж).
2.  **Live Activity Feed:** Лента событий в реальном времени (новый заказ, оплата получена, ошибка WhatsApp).
3.  **AI Value Block:** Эффективность рекомендаций (предложено / принято), средний чек с ботом vs без бота.
4.  **Actionable Alerts:** Блок проблем, требующих внимания (ошибки iiko, неоплаченные счета, зависшие диалоги).

---

## 3. Архитектура базы данных (Multi-tenant)

### Ядро (Core)
*   `organizations`: `id`, `name`, `slug`, `timezone`, `currency`.
*   `users`: `id`, `organization_id`, `email`, `role` (admin/operator).

### Коммуникации
*   `conversations`: `id`, `organization_id`, `phone`, `ai_paused`.
*   `messages`: `id`, `organization_id`, `conversation_id`, `provider_message_id` (wamid), `status` (sent/delivered/failed).

### Заказы и Продажи
*   `orders`: `id`, `organization_id`, `status`, `items_json`, `total_price`, `version` (optimistic lock).
*   `recommendation_events`: `id`, `order_id`, `item_id`, `accepted` (boolean), `reasoning`. Позволяет считать ROI бота.

---

## 4. Система уведомлений (Event-driven)

Система строится по принципу: **Event → Rule → Channel**.

*   **Триггеры:** Новый заказ, ошибка доставки сообщения, полученная предоплата, эскалация (бот не справился).
*   **Каналы:**
    *   `In-App`: WebSocket-уведомления в админке.
    *   `Telegram`: Оперативные алерты для персонала.
    *   `Push`: Уведомления в браузере/PWA.

---

## 5. UI Kit (Дизайн-система уровня Stripe)

*   **Цвета:** Глубокий Slate (`#0F172A`) для фона, Indigo (`#6366F1`) для бренда.
*   **Типографика:** Шрифт **Inter**. Заголовки — Bold, данные — Medium.
*   **Компоненты:**
    *   `Status Badges`: Мягкие цвета фона (прозрачность 10%) + яркий текст.
    *   `Empty States`: Вместо пустых таблиц — призыв к действию («Подключите WhatsApp», «Добавьте меню»).
    *   `Side Modals`: Детали заказа открываются в боковой панели, не перекрывая список.
