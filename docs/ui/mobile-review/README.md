## Итог (коротко)

- **Хорошая новость**: критического горизонтального overflow **нет**, ширина держится нормально; **tap targets** почти везде проходят \(≈44px\).
- **Плохая новость**: UX пока ощущается как **сжатая desktop-админка**, а не отдельный мобильный сценарий.

## Что улучшить

### 1) Мобильный первый экран (Dashboard)

Сейчас dashboard на `320px` тратит много места на заголовок, статус, описание и большую карточку.

- **Цель**: выше поднять пользу — **2–4 компактных KPI** сразу в первом экране.
- **Сделать**: длинные пояснения увести ниже или **свернуть**.

### 2) Заказы

На мобильном экране слишком много “управляющих” элементов до самих заказов: табы, кнопка, фильтр, подсказка, поиск.

- **Подсказка**: свернуть по умолчанию.
- **Фильтры**: перенести в **bottom sheet**.
- **`+ Новый заказ`**: сделать компактной **sticky/FAB**-кнопкой.
- **Контент**: список заказов показывать раньше (меньше “вертикального налога”).

### 3) Диалоги

Список выглядит аккуратно, но composer снизу уже виден на экране списка и съедает место.

- **Предложение**: паттерн **“список → отдельный экран чата”**:
  - пока чат не выбран — показывать только список;
  - после выбора — скрыть нижнюю навигацию и дать полноценный чат.

### 4) Настройки

На `412px` табы настроек начинают обрезаться справа.

- **Заменить горизонтальные табы** на:
  - компактный dropdown “Раздел настроек”;
  - либо segmented для первых 2–3 разделов + “Ещё”.
- **Внутри разделов**: использовать accordions, чтобы длинные карточки не превращались в полотно.

### 5) Нижняя навигация

Сама по себе работает, но пункт “Ещё” становится активным для настроек, хотя пользователь находится, например, в “Профиле” или “Интеграциях”.

- **Лучше**: показывать текущий раздел в header, например: **“Ещё / Интеграции”**.
- **Bottom nav**: оставить только как глобальный переключатель.

### 6) Визуальная плотность

Карточки местами слишком крупные для операционной админки.

- **Нужно**: уменьшить вертикальные отступы на мобильном, особенно в `orders`, `settings`, `dashboard`.
- **Правило**: крупные карточки оставлять только там, где они реально “рабочий объект”.

## План исправления (приоритеты)

### P0: Mobile Shell

Правим общий мобильный каркас:

- `app/templates/admin.html` (header, bottom nav, safe-area, единое поведение sticky-панелей)
- `src/css/admin-input.css` (мобильные отступы/плотность, поведение панелей/скролла)

### P1: Заказы + Диалоги

Самые важные ежедневные сценарии:

- **Заказы**: “список/канбан первым”, фильтры в sheet.
- **Диалоги**: master-detail mobile flow (“список → чат”).

### P2: Настройки

- Убираем горизонтальный перегруз табов.
- Группируем длинные блоки.
- Sticky save/action bar — только там, где есть несохранённые изменения.

### P3: Dashboard

- Пересобрать первый экран под владельца: KPI и вклад ИИ выше, длинные объяснения ниже.

### P4: Проверка

- Обновить/добавить Playwright mobile screenshots в `docs/ui/mobile-review/`.
- Запустить Lighthouse mobile через `scripts/run_admin_lighthouse.mjs`.
  - Артефакты Lighthouse: `docs/ui/lighthouse/summary.json` и таблица в `docs/ui/lighthouse/README.md`.

## Рекомендация

Начинать с **P0 + P1** — максимальный эффект для ежедневного использования админки.
