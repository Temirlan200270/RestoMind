## Промпт агенту

**Контекст совместной работы**

Ты — **ИИ 2**. В параллели с тобой работает **ИИ 1**, который ведёт **backend / платежи / очереди / тяжёлые сервисы** (`app/services/`, `app/api/payment_webhook.py`, миграции Alembic, интеграции iiko / WhatsApp core). Твоя зона по умолчанию — **админка (UI/UX), продуктовые экраны, аналитика-подача, документация для оператора**, без изменения платёжных вебхуков и без ломания контрактов API, которые сейчас делает ИИ 1.

**Правила параллели**

- Перед большими правками сверяйся с актуальным [IMPLEMENTATION_PLAN.md](../IMPLEMENTATION_PLAN.md) (колонка «Статус по эпикам»): не дублируй эпики, уже закрытые в текущем объёме (E17, E18).
- Пакет **ИИ 1** — `app/api/admin/*`, не трогай во время серии PR по **E0.1**; после каждого такого PR делай `git pull` (см. [PARALLEL_AI_PLAN.md §0 sync-точки](../PARALLEL_AI_PLAN.md)). Новый API под UI — тикет ИИ 1. Раньше путь назывался `admin.py`; сейчас это каталог `app/api/admin/`.
- Избегай одновременных конфликтующих правок с ИИ 1 в одних и тех же файлах: при правках в шаблонах/JS после merge ИИ 1 сначала **pull**, потом продолжай.
- ИИ 1 не должен править твои задачи по UX без необходимости; ты **не меняешь** `app/api/payment_webhook.py` и связанные платежные сервисы без явной договорённости.

**Приоритетные направления (по выбору заказчика)**

Уже в коде: полировка «Вклад ИИ», селектор филиалов (E2.1.F), ссылка на скачивание payload в Super Admin, мультиязычные константы E16 в `prompts.py` (см. [IMPLEMENTATION_PLAN.md](../IMPLEMENTATION_PLAN.md)).

1. **E2.2.F (следующий крупный UX):** «Мой ресторан → Брендинг» (лого, цвет, превью). Надёжнее после **E2.2.B** от ИИ 1: `GET/PATCH /api/admin/branding`, `POST .../branding/logo` (секция `# ── E2.2 ──`); до этого — форма на заглушке, в `/auth/me` поле `branding` остаётся placeholder.
2. **E3:** не дублировать агрегаты на фронте; при ошибке `ai-value` — fallback на `GET /api/admin/stats` (`loadAiValue`).
3. **E2.3.F (после биллинга):** блок лимитов в админке из `/auth/me`.
4. **Операторка:** «Ошибки» = тот же экран, что «Помощь клиентам».

**После работы:** короткая запись в [CHANGELOG.md](../CHANGELOG.md); точечные тесты при изменении Python; не создавай лишних markdown-файлов без запроса.
